# حالة تنفيذ تبويب Chat

آخر تحديث: 2026-09-18

## المنجز محليًا

- محادثات خاصة ثنائية فقط، بلا غرف جماعية.
- إنشاء المحادثة عبر `Public ID` مع تحقق العضوية في كل عملية.
- إرسال متفائل في Expo، إعادة المحاولة، ومنع التكرار عبر `clientMessageId`.
- رسائل محفوظة ساعتين ثم تُحذف فعليًا من Firestore بواسطة worker.
- Burn اختياري: المحتوى مقفول عند المستلم، يُفتح صراحةً، ثم يُحذف بعد 5 ثوانٍ.
- Pagination ثابت بمؤشر مركّب من وقت الرسالة ومعرّفها، حتى عند تساوي التوقيت.
- تحميل الرسائل الأقدم في Expo والويب دون تكرار مع الحفاظ على موضع التمرير.
- عداد غير المقروء و`firstUnreadMessageId` وفاصل `Unread` والانتقال لأول رسالة غير مقروءة.
- تصحيح عداد وأول رسالة غير مقروءة تلقائيًا عندما تنتهي صلاحية رسائل أقدم.
- تحديث المقروء داخل Firestore transaction متناسق مع وصول رسالة جديدة بالتزامن.
- حالة `Sent` و`Read` للرسالة العادية، و`Sent` و`Opened` لرسالة Burn عند المرسل.
- معالجة حذف الطرف الآخر: يبقى السجل المحتفظ به، يظهر `Deleted account`، ويُمنع الإرسال.
- Push Notifications حقيقية عبر Expo Push Service، مع تسجيل الجهاز وإلغاء تسجيله عند الخروج.
- الضغط على الإشعار يفتح المحادثة المطلوبة، ولا يحتوي الإشعار على نص الرسالة.
- عدم كشف نصوص الرسائل للأدمن؛ حتى preview الخادم عام (`Message` / `Burn message`).
- تطبيق Expo يستخدم TypeScript وNativeWind، ومدخل الرسالة يحافظ على معالجة الكيبورد الحالية.

## التحقق المحلي الحالي

- `npm run typecheck:api`: ناجح.
- `npm --prefix apps/api run typecheck:tests`: ناجح.
- `npm run test:api`: ناجح، 15 اختبارًا تشمل pagination، عدم تكرار الإشعار، القراءة،
  انتهاء الصلاحية، Burn، وحذف الطرف الآخر.
- `npm run typecheck:mobile`: ناجح.
- `npm run lint:mobile`: ناجح.
- `npm run typecheck:web`: ناجح.

سيُعاد تشغيل البناء الكامل قبل النشر.

## متطلبات تفعيل Push على الأجهزة

- إضافة `EXPO_PUBLIC_EAS_PROJECT_ID` إلى بيئة تطبيق الهاتف، أو ربط التطبيق بمشروع EAS يوفّر
  `Constants.easConfig.projectId`.
- إعداد بيانات FCM v1 لأندرويد وبيانات APNs لـiOS ضمن EAS credentials.
- استخدام development/release build؛ Push البعيد لا يعمل في Expo Go على أندرويد.
- `EXPO_PUSH_ACCESS_TOKEN` في الباك اختياري، ويصبح مطلوبًا فقط إذا فُعّلت Enhanced Push Security
  في لوحة Expo.

## ما يزال مطلوبًا قبل اعتبار Chat مكتملًا بالكامل

1. Realtime بدل polling المؤقت.
2. الرد، التفاعلات، التعديل، والحذف المحلي من الجهاز فقط.
3. الصور والكاميرا والملفات والصوت والموقع عبر خادم Media وروابط موقعة.
4. اختبار Push فعلي على Android وiOS بعد توفير EAS Project ID وcredentials.
5. Web Push للمتصفح منفصل عن Expo Push الخاص بتطبيق الهاتف.
6. حماية العرض/Blur وخيارات الخصوصية.
7. E2EE مؤجل حسب قرارنا الحالي، ولا نصف الرسائل بأنها مشفرة طرفًا لطرف.
