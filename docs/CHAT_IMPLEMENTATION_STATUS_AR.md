# حالة تنفيذ تبويب Chat

آخر تحديث: 2026-09-18

## المنجز والمرفوع إلى Staging

- محادثات خاصة ثنائية فقط؛ لا توجد غرف جماعية.
- إنشاء/استرجاع المحادثة اعتمادًا على `Public ID` بطول 50 حرفًا.
- التحقق من عضوية المستخدم في الخادم عند كل قراءة وكتابة وعلامة قراءة.
- قائمة المحادثات، آخر رسالة، العداد غير المقروء، وسجل الرسائل.
- إرسال نص حتى 4000 حرف مع `clientMessageId` لمنع تكرار الرسالة عند إعادة المحاولة.
- ربط Expo وNext.js بالـAPI الحقيقي وإزالة الرسائل والردود الوهمية من صفحة الويب الفعلية.
- واجهة متطابقة وظيفيًا للهاتف والويب: قائمة المحادثات، إنشاء محادثة، شاشة الرسائل، حالات التحميل والخطأ، وإعادة المحاولة.
- معالجة الكيبورد في Expo عبر `KeyboardProvider` و`KeyboardAvoidingView`.
- توثيق العقد في `docs/CHAT_API_V1.md`.

## المتبقي قبل اعتبار Chat مكتملًا

1. Realtime بدل polling المؤقت.
2. الرد على رسالة، التفاعلات، التعديل، والحذف المحلي من الجهاز فقط.
3. الصور، الكاميرا، الملفات، الرسائل الصوتية، والموقع باستخدام تخزين Media حقيقي وروابط موقعة.
4. حالات الإرسال/التسليم/القراءة بصورة نهائية، offline outbox، وإشعارات push.
5. حماية العرض/Blur وخيارات الخصوصية.
6. سياسة الاحتفاظ ساعتين وBurn بعد 5 ثوانٍ تحتاج موافقة صريحة قبل تفعيل أي حذف فعلي.
7. قرار E2EE وإدارة مفاتيح الأجهزة قبل وصف الرسائل بأنها مشفرة طرفًا لطرف.
8. Admin آمن يعرض المقاييس والبلاغات فقط ما لم يُتفق صراحة على غير ذلك، ويتطلب أولًا نظام مصادقة وصلاحيات للمدير.
