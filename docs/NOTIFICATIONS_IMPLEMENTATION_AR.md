# تنفيذ المرحلة الأولى للإشعارات

التاريخ: 1 أكتوبر 2026. الحالة: تنفيذ محلي؛ لم يُنشر ولم يُؤكد وصول Push على جهاز حقيقي.

## موضع الجرس

- الويب: بجانب زر المظهر في الهيدر المشترك لجميع صفحات المستخدم. الهيدر الإداري يضم جرسًا مستقلًا لتنبيهات الأدمن.
- الهاتف: بجانب زر المظهر في `FeatureScreen`، وأيضًا في هيدرات المحادثة وملف المستخدم وإنشاء الصفحة التي لها هيدر خاص. شاشة نشر أول منشور للصفحة تستخدم الآن الهيدر المشترك أيضًا.
- الجرس يظهر عدد غير المقروء حتى `99+`. يفتح قائمة على الويب وصفحة على الهاتف، مع فتح وجهة الإشعار وتعليم المقروء وتحميل المزيد وحالات الانتظار والخطأ والفراغ.
- أُزيل الجرس القديم المكرر من هيدر Social. بقي تبويب نشاط Social القديم للوصول إلى سجلاته السابقة؛ لا يُعاد إرسال تلك السجلات كإشعارات جديدة.

## الأحداث المربوطة الآن

| المجال | التنفيذ |
| --- | --- |
| Social | لايك مجمّع، تعليق دون كشف المعلّق المجهول، متابعة مع كبح التكرار السريع |
| Market | لايك مجمّع وتعليق على الإعلان |
| Chat | حدث إرسال محفوظ مع الرسالة، Push عام، صلاحية زمنية وفحص القراءة والحذف قبل الإرسال |
| الإدارة والدعم | رسالة شخصية، إعلان عام داخل الصندوق، Push للإعلان العام المصنف تحذيرًا، رد دعم |
| إجراءات الإدارة | إشعار إخفاء/استعادة/حذف/تعديل المحتوى، وتعليق/إعادة تفعيل الحساب |
| الفوترة | تأكيد شراء بعد تطبيق الرصيد، تعديل إداري، عبور حد الرصيد المنخفض والنفاد |
| بلاغات الأدمن | فرز عاجل لفئات محددة، وتجميع Push للبلاغات العادية مع بقاء كل بلاغ منفصلًا داخل الصندوق |
| مراجعة البلاغ | صفحة ويب حقيقية، إغلاق البلاغ وتسجيل القرار وإشعار النتيجة للمبلّغ داخل التطبيق |
| طلب الدعم للأدمن | داخل الصندوق فقط؛ تصنيف الدعم العاجل والتصعيد لم يُضفا بعد |

المكالمات تحتفظ بمسارات الرنين الأصلية: FCM على Android وAPNs VoIP على iOS؛ ليست سجلات مكالمات فائتة جديدة ضمن هذه المرحلة.

## Firebase والتوافق مع الهاتف

- الباك يستخدم `firebase-admin` الموجود لإرسال FCM، مع استمرار دعم Expo للأجهزة القديمة خلال تحديث التطبيق.
- الويب يستخدم Firebase SDK وservice worker من مسار TypeScript يولّد JavaScript، مع زر تفعيل إذن المتصفح وإعداد VAPID. التهيئة متزامنة عند بدء worker حتى لا تضيع معالجة أول Push بعد إعادة تشغيله.
- Android يأخذ FCM token الأصلي بواسطة Expo. خدمة `expo-callkit-telecom` الحالية تستقبل المكالمات وتحوّل الإشعارات العادية إلى Expo؛ لم تُضف خدمة FCM أصلية تنافسها.
- iOS أُضيف له `@react-native-firebase/app` و`messaging` بإصدار 26.4، مع إعداد CocoaPods بدل SPM وstatic frameworks عبر `expo-build-properties` المتوافق مع Expo 56. يتطلب بناء native جديدًا. [مرجع إعداد iOS الرسمي](https://rnfirebase.io/ios-spm).
- نقل مصدر البيانات إلى PostgreSQL لم يبدأ هنا. قاعدة المنتج الحالية تحفظ الصناديق والتفضيلات والأجهزة ومهمات الإرسال، وFirebase يوصّل Push.

## التحقق والتشغيل

عقد API موثق في [NOTIFICATIONS_API_V1.md](NOTIFICATIONS_API_V1.md). اختبارات جديدة تغطي الصلاحيات، فصل هويات الصفحات والأدمن، الخصوصية، تجميع اللايك والبلاغات، القراءة، الحظر، انتهاء الصلاحية، إعادة المحاولة، إعداد payload لأندرويد، تعطيل FCM tokens غير الصالحة، وتغيير حالة الحساب.

قبل اعتماد الوصول الفعلي:

1. استخدام بيانات Firebase web من المشروع الصحيح وVAPID في إعدادات الويب؛ أُضيف اسم المتغير إلى `.env.example` دون قيمة سرية.
2. التأكد من تفعيل Cloud Messaging وصلاحية service account الموجود في الباك، وإعداد APNs للإشعارات العامة داخل Firebase على iOS. إعداد APNs VoIP للمكالمات يبقى مستقلًا.
3. نشر API والويب إلى staging، وبناء iOS/Android جديدين من إعدادات Expo. وجود ملفات Firebase محليًا ليس إثباتًا لصحة الربط أو جاهزية الاعتمادات.
4. تجربة حسابين على الويب والهاتف: الخلفية والتطبيق المغلق، تعليق مجهول، صفحة تابعة، ضغط الإشعار بعد انتهاء الرسالة، قراءة على جهاز آخر، رفض الإذن، تسجيل الخروج وتغير token. اختبار رنين المكالمات أثناء ذلك للتأكد من استمرار المسار الأصلي.

أُجري فحص Expo config introspection، بما فيه entitlement الخاص بالإشعارات وstatic frameworks. لا يعوّض هذا بناء Xcode/Gradle أو تجربة جهاز حقيقي.

أُجري فحص autolinking: وحدتا React Native Firebase مربوطتان على iOS ومستبعدتان على Android، الذي يحتفظ بخدمة FCM الموجودة للمكالمات والإشعارات.

نتائج الفحص المحلي: `npm run typecheck` وtypecheck اختبارات API ناجحة؛ `npm run test:api` نجح بـ156 اختبارًا؛ بناء الويب وAPI ناجحان. lint الهاتف بلا أخطاء، مع تحذيرين في ملف Expo مولّد ومتغير غير مستخدم في مكوّن الصوت الموجود مسبقًا.

## ما بقي من الحصر

- المكالمات الفائتة، إعادة المشاركة، وفشل SMS النهائي.
- الردود على التعليقات، mentions، تنبيهات منشورات المتابَعين، والسعر لإعلان محفوظ؛ تتطلب ميزاتها الأصلية أولًا.
- الدخول من جهاز جديد موثوق، وأوقات الهدوء والتفضيل بين عدة أجهزة.
- تصاعد البلاغات وتأخر مراجعتها، الدعم العاجل، المصالحة المالية، مراقبة الخدمات والأمان والنسخ الاحتياطي وارتفاع فشل الاتصال؛ تحتاج قياسات ودورات عمل أو مراقبة مستقلة.
- أسباب القرارات الإدارية التفصيلية والاعتراض، وشاشة حالة الحساب المعلق؛ النص الحالي يوجه إلى الدعم، وتحقق الجلسة الحالي يمنع الحساب المعلق من قراءة API العادي.
- تجربة مرئية فعلية للهيدر على أجهزة صغيرة، وQA لحالات Push؛ لا توجد نتيجة مثبتة لإرسال حقيقي ضمن هذه المراجعة.

المهام المكتملة لا تُحذف تلقائيًا حاليًا، وسجلات الصندوق تبقى بعد انتهاء صلاحية Push. يجب تحديد سياسة احتفاظ لهذه البيانات قبل الإطلاق واسع النطاق. الإرسال يتحمل إعادة المحاولة لكنه ليس ضمانًا لوصول وحيد أو قراءة المستخدم.
