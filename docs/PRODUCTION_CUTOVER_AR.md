# تشغيل g000st على الدومين الأساسي

تاريخ التحويل: 10 أكتوبر 2026. الإصدار المنقول من staging هو
`35d723e2d42e28e38d256c8de45db34f7160dfb9`.

## توزيع الإنتاج

- `https://g000st.com`: تطبيق Next.js الجديد؛ يحول HTTP و`www` إلى هذا الأصل.
- `/api/v1/`: API المشترك للويب والهاتف، مع دعم WebSocket للمكالمات ورؤوس GeoIP الموثوقة.
- `g000st-web-production`: يستمع على `127.0.0.1:3002`، وإصداراته تحت `/root/production/g000st-web`.
- `g000st-api-production`: يستمع على `127.0.0.1:3101`، وإصداراته تحت `/root/production/g000st-api`.
- `https://media.g000st.com`: خدمة MinIO القائمة على `g000st-app`، ببياناتها وروابطها الحالية.
- الإعداد المعتمد في [Nginx الإنتاج](../infra/nginx/g000st-production.conf).

أُعيد بناء الويب مع `NEXT_PUBLIC_API_URL=https://g000st.com`، وصُححت روابط العودة من Stripe.
تُحفظ ملفات البيئة خارج الإصدارات، بصلاحية `600`. تُحفظ قائمة PM2 ليعود الإنتاج بعد إعادة
تشغيل السيرفر.

## البيانات والتوافق

استُخدمت بيانات النسخة الجديدة القائمة في Firestore دون تغيير أسماء مجموعاتها أو Pepper
الاستعادة أو مفاتيح التخزين. بقي الاسم التاريخي `staging_v1` لبادئة مجموعات **الإنتاج** حتى لا
تنكسر الحسابات أو الفهارس أو علاقاتها. هذا الاسم لا يعني أن البيانات ما زالت بيئة تجريبية.
لم تُدمج حسابات التطبيق القديم ذات العقود المختلفة في التطبيق الجديد.

يحوّل `staging.g000st.com` صفحات المتصفح إلى الإنتاج. يستمر `/api/v1/` على هذا الاسم بتمرير
الطلبات مباشرة إلى API الإنتاج، بما فيها POST وWebSocket، للتوافق مع التطبيقات المثبتة
وStripe وTelnyx التي قد تحتوي عنوان staging. الإعداد في
[ملف التوافق](../infra/nginx/g000st-staging-compatibility.conf).

**staging لم تعد بيئة اختبار مستقلة.** طلبات API عليها تتعامل مع بيانات الإنتاج. يمنع وجود
`/root/production/staging-compatibility` سكربت نشر staging من العمل. قبل إعادة staging يجب
تجهيز بادئة Firestore ومفاتيح وسائط معزولة، وإعادة توجيه Nginx إلى خدمات staging مستقلة، ثم
إزالة ملف الحماية. لا يُستخدم حساب اختبار قائم على staging لتجربة تغييرات قد تحذف بيانات
الإنتاج.

## نشر الإصدارات التالية

[Deploy production](../.github/workflows/deploy-production.yml) ينشر `web` أو `api` أو `both`
من `main`. يعيد استعمال GitHub Environment الحالية المسماة `staging` كمخزن لبيانات SSH
الخاصة بالسيرفر؛ لا ينشر إلى خدمات staging. اسم مخزن الأسرار تاريخي، ولا يدل على عزل
بيانات التشغيل. يشترك مسارا النشر في قفل يمنع بناء إصدارين على السيرفر في وقت واحد.

أُثبت `/usr/local/sbin/g000st-deploy-production` من
[سكربت الإنتاج](../infra/deploy/deploy-production.sh)، وأُعطي مستخدم `g000st-deploy` صلاحية
تشغيله عبر sudo. يتحقق من هوية artifact ومساراته، يفحص الأنواع والاختبارات، يبني الإصدار،
ويتحقق من الصحة المحلية والعامة، ويعيد الإصدار السابق تلقائيًا عند فشل التفعيل. تبقى ملفات
البيئة وحساب Firebase خارج Git وartifacts. يظهر workflow الجديد على GitHub بعد رفع تعديل
المستودع.

## النسخ الاحتياطية والرجوع

النسخ محفوظة على كل سيرفر في `/root/backups/production-cutover-20261010` بصلاحيات مقيدة:
إعدادات Nginx وقائمة PM2 وملفات التطبيق القديم. يوجد على السيرفر الأساسي أيضًا نسخة ملفات
البيئة وبيانات Firestore الخاصة بالنسخة الجديدة بصيغة JSONL تضم مسار المستند وحقوله الأصلية،
بما فيها المجموعات الفرعية. هذه نسخة منطقية يدوية، وليست snapshot ذرية أو بديلًا لسياسة
نسخ احتياطي دورية. لا تُنقل إلى مستودع Git.

تُحفظ مصادر التطبيقات القديمة وملفاتها للإرجاع فقط. أُخرجت عملياتها من قائمة PM2 المحفوظة؛
لم يُنسخ أي مصدر قديم إلى `main`. عند ضرورة الرجوع تُوقف خدمات الإنتاج أولًا، وتُستعاد
إعدادات Nginx والعمليات السابقة من النسخة الخاصة. لا تُشغّل API القديمة والجديدة بالتوازي
على البيانات نفسها لفترة ممتدة لأن لديهما عمالًا خلفيين.

## الدفع

فُعّل **Stripe Live** في 10 أكتوبر 2026 بعد تحويل الدومين. حُفظ المفتاح المقيد وسر توقيع
webhook في ملف بيئة API المشترك بصلاحية `600`، وأُعيد تشغيل API وحفظ قائمة PM2.
الوجهة القائمة في حساب Stripe تستخدم Snapshot وحدث `checkout.session.completed` على
`https://g000st.com/api/v1/billing/webhooks/stripe`. روابط عودة الويب تستخدم دومين الإنتاج.
توجد نسخة خاصة من الإعدادات السابقة تحت `/root/backups/stripe-live-20261010-*`.

نجح إنشاء جلسات Live عبر مسار شراء التطبيق للويب والهاتف، والتحقق من المبلغ والعملة
والبيانات الوصفية، ثم إغلاق الجلسات دون دفع. نجح إرسال طلب تشخيص موقع بالسر الجديد
بحالة غير مدفوعة دون إضافة رصيد، ورُفض الطلب غير الموقع. نُظف حساب الفحص المؤقت.
هذه الفحوص لا تثبت تسليم حدث دفعة حقيقية من Stripe أو إضافة رصيدها؛ يبقى ذلك لأول شراء فعلي.

## التحقق بعد التحويل

نجحت فحوصات الأنواع وبناء الويب والـAPI، واختبارات API وعددها 202. نجحت اختبارات فعلية على
دومين الإنتاج للتسجيل والاستعادة وتدوير الجلسات وإبطال إعادة استخدامها، ولإرسال واستقبال
رسالة وعداد غير المقروء وحالة القراءة. صُحح توقع قديم في سكربت فحص المحادثة ليتوافق مع
الاستجابة الموثقة `200` وحقل `readState`؛ لم يتغير سلوك المنتج لهذا السبب.

نجح اتصال WebSocket مشفر، وإصدار بيانات TURN، ورفع صورة صغيرة برابط موقع وتنزيلها مع
مطابقة محتواها ورؤوس CORS. نجحت قراءة مسارات Social وMarket وContacts والإشعارات والفوترة
بحساب اختبار، ورُفض Origin غير مسموح. وصلت طلبات webhooks غير الموقعة على الدومين الأساسي
ومسار التوافق إلى معالجات التحقق ورُفضت بتوقيع غير صالح؛ هذا لا يثبت عملية دفع أو اتصال
مدفوع فعلية.

نجح فحص المتصفح بحجم شاشة كمبيوتر وهاتف دون أخطاء JavaScript أو ردود 5xx، وكانت طلبات
العميل إلى `g000st.com`. جرى تنظيف حسابات وملفات اختبارات الفحص، وبقي عدد الحسابات الأصلية
كما كان قبل التحويل. خدمة MinIO بقيت سليمة بعد إيقاف التطبيق القديم على سيرفر الميديا.
