## بنية المستودع

```text
apps/
  api/       Node.js API المشترك
  mobile/    Expo SDK 56 لتطبيق iOS وAndroid
```

القديم والأدمن فهما مرجعان للمطابقة البصرية والسلوكية فقط.

  الضرورية فقط.

  تجهيز تخزين مناسب ونسخ احتياطي.
- Firestore باقية في المرحلة الحالية. قرار PostgreSQL منفصل ويؤجل إلى ما بعد استقرار المنتج.

## GitHub Actions والنشر

الـworkflow موجود في `.github/workflows/deploy-staging.yml` واسمه `Deploy staging`.

- تشغيله يدوي عبر `workflow_dispatch`.
- الخيارات: `web` أو `api` أو `both`.
- يعمل من `main` فقط.
- عند اختيار `both` ينشر API أولًا ثم الويب.
- يشغّل typecheck/tests/build المناسبة قبل الرفع.
- لا يضع `.env` داخل حزم النشر.
- يبني release مستقلًا على السيرفر ويبدّل symlink ذريًا.
- يفحص الخدمة بعد النشر ويعمل rollback تلقائيًا عند الفشل.
- يستخدم حساب SSH مقيّدًا، وليس root أو حسابًا شخصيًا.

أول تشغيل حقيقي للويب نجح:

- GitHub run: `35107662675`
- commit: `bec383d7cdbc8aaf1e84c79b9fa18a28c57ba6b4`
- النتيجة: `success`
- المدة: دقيقتان و6 ثوانٍ.

بسبب عدم امتلاك المستخدم صلاحية GitHub Environments، أضيفت القيم حاليًا كـRepository secrets.
هذا عمل بنجاح. الأسماء المطلوبة فقط، من دون تسجيل قيمها، هي:

- `DEPLOY_SSH_HOST`
- `DEPLOY_SSH_USER`
- `DEPLOY_SSH_PRIVATE_KEY`
- `DEPLOY_SSH_KNOWN_HOSTS`

المنفذ الافتراضي داخل الـworkflow هو `22`، لذلك `DEPLOY_SSH_PORT` اختياري. عند توفر صلاحية
Environments لاحقًا يفضل نقلها إلى Environment باسم `staging` مع reviewer وحصر الفرع بـ`main`.

## الأمان والأرشفة

- المستودع عام؛ لا تضع فيه IP خاصًا غير ضروري أو مفاتيح أو ملفات `.env` أو Recovery IDs.
- نسخة خاصة من المواد القديمة والحساسة محفوظة محليًا خارج المستودع بصلاحيات مقيدة.
- مفتاح GitHub Actions الخاص محفوظ محليًا خارج المستودع ولم يُرفع إلى Git.
- مستخدم النشر على الخادم لا يملك عبر sudo إلا تشغيل سكربت staging المحدد.
- الملفات القديمة القابلة للرجوع موجودة في فرع الأرشيف بدل بقائها مبعثرة في `main`.

## التشغيل محليًا

من جذر المشروع:

```bash
npm ci
npm run dev:web
npm run dev:mobile
```

لتشغيل Expo Web على منفذ مختلف عند انشغال 8081:

```bash
npm --prefix apps/mobile run web -- --port 8082
```

يمكن تشغيل الواجهتين محليًا مع باك staging ولا يلزم تشغيل API محليًا لهذا السيناريو.

## ما لم يكتمل بعد

- لم يُختبر مسار نشر `api` عبر GitHub Action بعد؛ مسار `web` فقط هو الذي اختُبر فعليًا.
- يجب إجراء QA يدوي كامل لتدفق Register → Copy ID → Login → Refresh → Logout على staging.
- يجب متابعة مطابقة صفحات Expo صفحة بصفحة مع `appfg000st.html` وربط كل الخدمات الحقيقية.
- يجب مراجعة الويب والأدمن لاحقًا وتحسين ما أنشئ سابقًا عند الوصول إلى كل جزء.
- إعداد خادم الميديا وvolume/S3-compatible storage لم يبدأ بعد.
- قرار حذف البيانات النهائي وقاعدة البيانات المستقبلية مؤجلان للنقاش.
- اسم مستودع GitHub لم يتغير بعد من `g000st-ios` إلى `g000st`.
